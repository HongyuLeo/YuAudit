# Fictional demo expectations

All data is generated by `yuaudit/demo.py`, with fictitious supplier and identifiers.

| SKU | Expected finding |
|---|---|
| GOOD-01 | No exception |
| QTY-02 | PO 10 vs invoice 9, quantity difference -1 |
| PRICE-03 | PO USD 4.00 vs invoice USD 4.50, difference 0.50 |
| MISSING-04 | PO item absent from invoice |
| DUP-05 | Identical invoice rows; duplicate finding + aggregation unverified for PO/invoice and invoice/packing |
| FUZZY-0G | Candidate FUZZY-06 requires manual SKU confirmation; no automatic acceptance |
| EXTRA-08 | Invoice item absent from PO |
| BATCH-07 | Invoice 001 qty 40 + invoice 002 qty 60 = PO 100; each packing reference agrees; no exception |

Expected: **8 findings**, 7 distinct finding codes. The invoice contains two legitimate batch references in the same file. Invoice identifiers are repeated across line items normally; only identifiers reused across separate imported invoice documents trigger duplicate-invoice detection.

Additional automated tests cover declared partial 40/100 (informational unverified balance, not quantity error), over-shipment, mismatched/missing currencies, missing references, decimal arithmetic, totals, source evidence and exports.
